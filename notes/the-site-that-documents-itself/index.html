The site that documents itself.

This site was built by an AI agent under a designer's direction, inside a design system that explains itself. Notes on the architecture that keeps that honest.

August 2026

The drift

Documentation has one chronic disease: it drifts. A document describes the thing as it stood on the day of writing, the thing keeps moving, and every day after that the document is a little more fiction. Design systems die exactly this way. The library says one thing, production does another, and the moment a team notices the gap it stops trusting the library, which was the only job the library had.

The move this site makes against drift is architectural rather than disciplinary. No layer describes another layer from memory; each layer reads from the one below it. The rest of this note is just showing what that means.

The architecture

One stylesheet is the truth. Every colour and every space on the site is a token in it, and the reasoning sits next to the values as comments: not what a rule does, but why it is allowed to exist.

The system page documents the stylesheet, but it does not quote it. It reads it: the palette, the metrics and the motion tables are filled at load from the live values, so when a token changes, the documentation changes in the same second. It cannot go stale, because it stores nothing.

A checker holds the law. One script walks every page and fails the build if a colour or a space appears outside the tokens, if a colour misses one of the two schemes, if a hover goes unguarded, or if a long dash slips into the text. What the stylesheet permits, the checker enforces.

And the agent reads all three before it draws. Every page here was built by an AI agent working in this repository under my direction: it reads the stylesheet's reasoning, the system page's rules and the checker's verdicts, and what it builds lands back in the stylesheet, where the next round starts from.

The refusals

The system's principles are not written as aspirations. They are written as refusals, and that is what makes them teachable: an AI cannot hold taste, but it can hold a no. A few of the standing ones:

One size of type One text size and one display size. Hierarchy is carried by weight and grey, never by scale.
Eight spaces Every gap on the site is one of eight steps, 5 to 80 pixels. A ninth does not get invented for a special case.
Nothing is a card Zero corner radius, zero shadows, nothing floats. Structure is a hairline and some space.
Hover is a pointer idea Every hover rule sits behind a guard, so a touch screen never meets half of one.
A cut leaves at the edge A screen leaving an image's edge always leaves at a plate's edge. Inside a plate, nothing is cut.
No long dashes Not one, in any page's text. The checker fails the build that tries.
Claims from my mouth only The site states nothing about the work I have not said myself. A missing fact gets a visible slot, not a guess.
The page never moves Layout is set from the first frame. What arrives on a first view is the ink and the lines; nothing slides, nothing scales.

Where a rule comes from

The refusals are not designed up front. They get caught. The plate rule above started on a phone: the Donkey Republic case had screens cropped by their images' edges, standing in fields of slightly mismatched grey, and it read as broken rather than intended. The first idea was to mark every cut with a line where the screen goes under. What shipped instead was an arrangement: the plates dropped their padding so the greys fuse into one surface, and the images took places where every cut lands on a plate's edge, where running off reads as deliberate.

Then the decision was written down, in the stylesheet, at the spot where it is enforced. That is the working relationship in one story: I bring the taste call, the agent brings the build, and the rule outlives the conversation because it lives where the machine reads.

The repository keeps the same voice all the way down. The log reads as the site's own logbook; every commit says what the site did, not what a developer did:

The work opens: one page per case The wall replaced the drawers, and every case got an address of its own.
The clips fuse, and the measurement retires iOS renders video colour its own way, so instead of measuring the grey, the plates fused and the clips' own grey became the ground.
The rubber band comes back A scroll fix took away the bounce a phone needs to feel like a phone. The commit that returns it says why.
The face becomes Switzer The whole face swap in one commit, so one command can take it back.

Building with it

Extending the site is now mostly asking. The agent already knows the bands, the tokens and the refusals; the checker referees every change; and anything new that earns a rule gets the rule written where the next build will read it.

This is the same architecture as the prototyping harness at e-conomic: a design system on GitHub, explained to a model before it draws, so that what gets built wears the product's own clothes from the first pass. That work is the subject of the first note. This site is where I keep the discipline in practice.

In short

Documentation that describes a thing will drift from it. Documentation that reads the thing cannot. And a system turns out to be the set of sentences that say no: write those down where a machine can read them, and the machine can keep them too.
